# 人物卡（Character Card）规范与模板

## 一、数据库结构

人物卡存储于 `rpg_characters` 表，核心字段如下：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | TEXT (UUID) | 主键 |
| `user_id` | TEXT | 创建者用户 ID |
| `name` | TEXT | 角色名称 |
| `spec_version` | TEXT | SillyTavern V2 兼容版本号（固定为 `2.0`） |
| `card_data` | TEXT (JSON) | **角色卡核心数据**（下方详述） |
| `avatar_url` | TEXT | 头像 URL（可选） |
| `system` | TEXT | 规则体系：`dnd5e` / `coc7th` / `shadowrun` / `custom` |
| `char_type` | TEXT | 类型：`universal`（通用） / `dedicated`（专用） |
| `seed_price` | INTEGER | 价格（SEED），0 为免费 |
| `is_public` | INTEGER | 是否公开（0/1） |
| `license_type` | TEXT | 授权模式：`full_copy` / `reference_only` |

## 二、人物卡类型对比

| 维度 | 通用型 (universal) | 专用型 (dedicated) |
|------|-------------------|-------------------|
| 用途 | NPC 模板，可跨副本复用 | 绑定特定副本的关键角色 |
| 定价 | 低价或免费（0~80 SEED） | 中等定价（60~150 SEED） |
| 属性 | 可省略或简化 | 完整属性、技能、装备 |
| 规则 | 多使用 custom | 根据副本使用 dnd5e/coc7th/shadowrun |
| 来源 | 世界书 NPC 剥离 / 社区创作 | 副本作者定制 |
| 关联 | 通过 asset_links 关联世界书 | 通过 campaign 关联副本 |

## 三、card_data JSON 规范

`card_data` 字段存储完整的角色卡数据，格式与 **SillyTavern V2 规范**兼容。

### 3.1 顶层结构

```json
{
  "name": "角色名称",
  "description": "角色简介（1-3句话）",
  "personality": "性格描述（简洁概括）",
  "scenario": "初始场景设定",
  "first_mes": "AI GM 首次遇到该角色时的开场白",
  "mes_example": "对话示例（用于引导 AI 的角色扮演风格）",
  "system_prompt": "角色专属系统提示词（覆盖 GM 默认提示）",
  "post_history_instructions": "历史对话后的额外指令（可选）",
  "tags": ["标签1", "标签2"],
  "creator": "创作者署名",
  "character_version": "版本号",
  "trpg": {
    "system": "dnd5e | coc7th | shadowrun | custom",
    "level": 1,
    "attributes": { ... },
    "skills": { ... },
    "hp": { "current": 10, "max": 10 },
    "mp": { "current": 10, "max": 10 },
    "san": { "current": 60, "max": 65 },
    "equipment": ["物品1", "物品2"],
    "spells": ["法术1", "法术2"],
    "backstory": "角色背景故事",
    "inventory": [
      { "name": "物品名", "quantity": 1, "description": "描述" }
    ]
  }
}
```

### 3.2 字段详解

#### 基础字段（必填）

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `name` | string | 角色名称，需唯一（同类型下不可重名） | `"散修老者·李清尘"` |
| `description` | string | 1-3 句话介绍角色身份和特征，AI 会以此为基础构建印象 | `"一位出生于晨风森林的精灵游侠，自幼与自然为伴。"` |
| `personality` | string | 性格关键词或短句，多个特质用顿号/逗号分隔 | `"冷静、敏锐，对自然万物怀有深深的敬畏"` |
| `first_mes` | string | 角色首次登场时的台词，引导 AI 的角色呈现方式 | `"嘘……别吓到它。她轻声说道。"` |

#### 基础字段（强烈推荐）

| 字段 | 说明 | 示例 |
|------|------|------|
| `scenario` | 角色通常出现的场景设定，帮助 AI 理解角色所处环境 | `"黄昏时分的林间空地，她正在照料受伤的鹿灵。"` |
| `tags` | 标签数组，用于搜索和分类 | `["导师","散修","炼药"]` |
| `creator` | 创作者署名 | `"雾隐工坊"` |
| `character_version` | 版本管理 | `"1.0"` |

#### 基础字段（可选）

| 字段 | 说明 |
|------|------|
| `system_prompt` | 角色专属系统提示词。如果留空，AI GM 使用预设的规则提示词 |
| `mes_example` | 对话示例，展示角色的说话风格。格式为 `<|user|>` 和 `<|assistant|>` 交替 |
| `post_history_instructions` | 在长对话后追加的额外指令 |

#### TRPG 扩展字段

`trpg` 对象包含规则系统所需属性：

| 子字段 | 说明 | 按规则系统 |
|--------|------|-----------|
| `system` | 规则体系标识 | dnd5e / coc7th / shadowrun / custom |
| `level` | 角色等级/强度 | dnd5e: 1-20, coc7th: 职业等级, shadowrun: 累计 karma |

**attributes（属性）按系统差异：**

| 系统 | 属性字段 |
|------|---------|
| dnd5e | 力量、敏捷、体质、智力、感知、魅力（范围 3-20） |
| coc7th | 力量、体质、体型、敏捷、外貌、智力、意志、教育、幸运（范围 3-99） |
| shadowrun | 力量、敏捷、体质、智力、意志、魅力、边缘、魔法/共鸣（范围 1-12） |
| custom | 自由定义，通常使用简化版 |

**skills（技能）按系统：**

| 系统 | 技能格式 |
|------|---------|
| dnd5e | `{"技能名": 加值}`，如 `{"察觉": 6, "隐匿": 8}` |
| coc7th | `{"技能名": 技能值}`，如 `{"侦查": 70, "心理学": 65}` |
| shadowrun | `{"技能名": 骰池数}`，如 `{"潜入": 7, "火器": 6}` |
| custom | 可选，可省略 |

**hp/mp/san：**

| 字段 | 适用系统 | 说明 |
|------|---------|------|
| `hp` | 全部 | `{ "current": 45, "max": 45 }` |
| `mp` | dnd5e（施法者）/ shadowrun（魔法师） | `{ "current": 30, "max": 30 }` |
| `san` | coc7th 专属 | `{ "current": 60, "max": 65 }`，理智值 |

## 四、创建人物卡流程

### 4.1 通过 API 创建

```
POST /api/rpg/characters
Content-Type: application/json
Authorization: Bearer <token>

{
  "name": "角色名称",
  "card_data": { ... },     // 上述 JSON 对象
  "char_type": "universal", // 或 "dedicated"
  "seed_price": 0,          // 价格（SEED）
  "system": "custom"        // 规则体系
}
```

### 4.2 上架到异界世场

创建后需通过市场 API 上架才能被其他用户购买和使用：

```
POST /api/rpg/market
{
  "asset_type": "character",
  "asset_id": "<角色ID>",
  "price": 60,
  "license_mode": "full_copy"
}
```

### 4.3 关联世界书/副本

通过资产链接建立关联，AI GM 运行时自动注入上下文：

```
POST /api/rpg/asset-links
{
  "source_type": "lorebook",
  "source_id": "<世界书ID>",
  "linked_type": "character",
  "linked_id": "<角色ID>",
  "role": "NPC"  // NPC | playable_npc | quest_giver | merchant
}
```

## 五、创作规范

### 5.1 命名规范

- 格式：`角色名·特质`（通用 NPC）或 `角色名`（专用角色）
- 名称中可使用 `·` 分隔角色身份和本名
- 建议包含足够的身份暗示，方便搜索

### 5.2 标签规范

推荐标签体系：

| 类别 | 标签示例 |
|------|---------|
| 身份 | `导师` `商人` `护卫` `刺客` `施法者` `游侠` |
| 阵营 | `正道` `邪道` `中立` `混乱` `守序` |
| 关系 | `NPC` `可玩角色` `任务发布者` `交易者` |
| 主题 | `修仙` `科幻` `克苏鲁` `末世` `奇幻` `赛博` |

### 5.3 定价参考

| 角色类型 | 推荐价格 | 说明 |
|---------|---------|------|
| 简易 NPC（无 TRPG 属性） | 0 SEED（免费） | 从世界书剥离的基础 NPC |
| 标准通用角色 | 30~60 SEED | 有完整背景和 personality |
| 精品通用角色 | 60~120 SEED | 有完整 TRPG 属性、装备、法术 |
| 副本专用角色 | 80~150 SEED | 深度绑定副本剧情，有专属设定 |

## 六、SillyTavern V2 兼容说明

本系统人物卡与 SillyTavern V2 规范兼容。差异仅在于：

- ST V2 使用包装格式：`{ "spec": "chara_card_v2", "spec_version": "2.0", "data": { ... } }`
- 本系统将 `spec` 信息存储在 `rpg_characters` 表的列中，`card_data` 直接存储内部数据对象
- 导出时系统自动组装为 ST V2 完整格式
- 导入时系统自动解析 ST V2 格式并提取 `data` 部分
