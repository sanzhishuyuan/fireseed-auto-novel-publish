# 世界书（Lorebook）规范与模板

## 一、什么是世界书

世界书（Lorebook / Worldbook）是 AI 跑团的"规则引擎"和"知识库"。它定义了世界观、规则、地理、势力等背景知识，AI GM 在运行时根据玩家行动关键词**自动匹配**相关条目，注入到对话上下文中，确保叙事的一致性和深度。

**设计定位：** 世界书是**轻量化的规则引擎**，只保留规则和知识设定。NPC 相关内容已剥离为独立的人物卡（通过资产链接关联），世界书专注于"这个世界是什么样的、有哪些规则"。

**与人物卡的核心区别：**

| 维度 | 世界书 | 人物卡 |
|------|--------|--------|
| 内容 | 规则、地理、势力、历史 | 角色属性、性格、背景 |
| 交互方式 | 关键词触发，自动注入上下文 | 玩家选用，AI GM 控制 |
| 复用性 | 跨副本共享（如克苏鲁设定集） | 跨副本扮演（如通用 NPC） |
| 定价 | 按条目数和质量定价 | 按角色深度和稀有度定价 |

## 三、条目（Entry）规范

世界书的核心是 `entries` 字段——一个 JSON 数组，存储所有条目。

### 3.1 条目数据结构

```typescript
interface LorebookEntry {
  id: string;              // UUID，唯一标识
  keys: string[];          // 触发关键词（核心！）
  content: string;         // 条目内容（世界知识）
  enabled: boolean;        // 是否启用
  selective: boolean;      // 是否条件触发（需副关键词匹配）
  priority: number;        // 优先级（0-99，越高越优先注入）
  secondary_keys?: string[];  // 副关键词（仅 selective=true 时生效）
  constant?: boolean;      // 是否常驻（始终注入，不依赖关键词匹配）
}
```

### 3.2 字段详解

#### `keys` — 触发关键词（最重要）

- 玩家行动或对话中出现这些关键词时，AI GM 自动匹配该条目
- 每个条目推荐 **2-5 个关键词**，包括主名称和常用变体
- 关键词区分大小写？不区分，AI GM 全部转为小写匹配
- 关键词可以是：地名、人名（已剥离到人物卡）、物品名、概念名

**好示例：** `["新上海", "上海", "城市"]`
**差示例：** `["```json", "变量说明"]`（这些是 Markdown 语法残留，不是真实关键词）

**原则：** 关键词应该是玩家**真正可能在对话中提到**的词汇。

#### `content` — 条目内容

- AI GM 匹配到关键词后，将 content 注入到 System Prompt 中
- 用简洁、清晰的描述性语言
- 长度建议 50-300 字（太短信息不足，太长浪费 Token）
- 可以包含 Markdown 格式（AI 能够理解）

#### `priority` — 优先级

- 范围：0-99，默认 10
- 数值越高，条目在注入列表中的排序越靠前
- 常驻条目（constant）建议 priority 设为最高（如 99），确保总是排在前面
- 一般知识条目建议 5-10，细节条目 1-4

#### `constant` — 常驻标记

- `true`：**始终注入**到 AI GM 上下文中，不依赖关键词匹配
- `false`（默认）：仅当关键词被触发时注入
- 应用场景：世界书的核心元数据、全局规则、关键设定

**注意：** constant 条目会被无条件注入到每个 AI GM 请求中，会持续消耗 Token。建议**限制在 3-5 条以内**，仅包含最核心的设定。

#### `selective` — 条件触发

- `false`（默认）：只要 keys 中任一关键词匹配，就注入
- `true`：需要 keys 和 secondary_keys **同时匹配**才注入
- 用于精细化控制：例如"魔法"条目只在玩家同时提到"施法"时才注入

### 3.3 条目分类建议

| 分类 | 推荐 priority | 说明 |
|------|--------------|------|
| 全局元数据 | 99（constant） | 世界观核心设定，始终注入 |
| 核心规则 | 50-80 | 战斗规则、升级体系、资源规则 |
| 地理区域 | 20-40 | 国家、城市、重要地点 |
| 势力组织 | 15-25 | 组织、派系、行会 |
| 历史事件 | 10-15 | 背景故事、传说 |
| 人物（已剥离） | — | 不再放入世界书，改用人物卡 |
| 细枝末节 | 1-5 | 冷知识、小地名 |

## 四、AI GM 条目匹配机制

```
玩家输入："我要去新上海的地下黑市买情报"
     ↓
遍历所有 enabled 条目：
  ┌─────────────────────────────────────┐
  │ 条目1: keys=["新上海","上海","城市"]  │ ← 匹配 "新上海"
  │ 条目2: keys=["企业","公司","集团"]    │ ← 不匹配
  │ 条目3: keys=["地下世界","深渊层"]     │ ← 匹配 "地下"
  │ ...                                │
  └─────────────────────────────────────┘
     ↓
按 priority 降序排序 → 取前 8 条
     ↓
注入到 System Prompt 的「世界百科」段落
     ↓
AI GM 在叙事中自然引用这些信息
```

**匹配逻辑详解：**

1. 过滤：只处理 `enabled=true` 的条目
2. 常驻：`constant=true` 的条目无条件加入结果
3. 关键词匹配：检查玩家**当前行动**和**最近 5 条消息**中是否包含任一 `keys`
4. 条件匹配：`selective=true` 的条目还需要 `secondary_keys` 中的任一关键词被匹配
5. 排序：按 `priority` 降序
6. 截断：最多取 **8 条**（避免上下文过长）

## 五、世界书创建流程

### 5.1 通过 API 创建（先创建空书，再逐条添加）

```
POST /api/rpg/lorebooks
Content-Type: application/json
Authorization: Bearer <token>

{
  "name": "世界书名称",
  "description": "简介",
  "entries": [
    {
      "keys": ["关键词1", "关键词2"],
      "content": "条目内容...",
      "priority": 10,
      "constant": false,
      "selective": false
    }
  ],
  "is_public": 1,
  "seed_price": 100
}
```

**响应：**

```json
{
  "success": true,
  "data": {
    "id": "自动生成的 UUID",
    "entries": [ ... ]  // 条目已被分配 id
  }
}
```

### 5.2 条目级操作 API

创建后可通过以下操作管理条目：

**添加条目：**
```
PUT /api/rpg/lorebooks/<id>
{
  "action": "add_entry",
  "entry": {
    "keys": ["新关键词"],
    "content": "条目内容...",
    "priority": 10,
    "constant": false
  }
}
```

**更新条目：**
```
PUT /api/rpg/lorebooks/<id>
{
  "action": "update_entry",
  "entryId": "<条目ID>",
  "entry": {
    "keys": ["修改后的关键词"],
    "content": "修改后的内容",
    "priority": 15
  }
}
```

**删除条目：**
```
PUT /api/rpg/lorebooks/<id>
{
  "action": "remove_entry",
  "entryId": "<条目ID>"
}
```

**启用/禁用：**
```
PUT /api/rpg/lorebooks/<id>
{
  "action": "toggle_entry",
  "entryId": "<条目ID>"
}
```

### 5.3 整体更新

```
PUT /api/rpg/lorebooks/<id>
{
  "name": "新名称",
  "description": "新简介",
  "entries": [ 完全替换所有条目 ],
  "is_public": 1
}
```

### 5.4 删除

```
DELETE /api/rpg/lorebooks/<id>
```
（会自动解除所有关联该世界书的副本的引用）

### 5.5 上架到异界世场

```
POST /api/rpg/market
{
  "asset_type": "lorebook",
  "asset_id": "<世界书ID>",
  "price": 100,
  "license_mode": "full_copy"
}
```

## 七、创作规范

### 7.1 世界书的"轻量化"原则

世界书的内容应该专注于**规则和知识**，而非具体的角色：

| ✅ 应该放入 | ❌ 不应放入 |
|-----------|-----------|
| 世界观核心设定 | NPC 详细背景（改用人人物卡） |
| 地理和区域描述 | 可交互角色的对话 |
| 势力和组织架构 | 玩家角色的属性 |
| 规则和机制说明 | 副本预设的剧情线 |
| 历史事件和传说 | 特定副本的流程说明 |

### 7.2 关键词设计规范

关键词是决定 AI GM 能否正确引用的关键，需要精心设计：

**好关键词的特征：**
- 真实反映条目内容的核心概念
- 包含常见变体（全称、简称、同义词）
- 玩家在对话中**大概率会使用**的词汇
- 不同条目间的关键词避免重叠/冲突

**关键词数量建议：**

| 条目类型 | 关键词数 | 示例 |
|---------|---------|------|
| 核心设定 | 2-3 个 | `["新上海", "上海"]` |
| 组织/地点 | 3-5 个 | `["昊天集团", "昊天", "生物工程"]` |
| 规则说明 | 2-4 个 | `["修仙境界", "境界", "突破"]` |
| 冷知识 | 3-4 个 | `["阿卡姆精神病院", "阿卡姆", "精神病院"]` |

**注意避免：** 不要使用 Markdown 格式字符作为关键词（如 `"```json"`、`"## 标题"` 等），AI GM 的关键词匹配是基于对话内容，玩家不会在对话中输入这些格式符号。

### 7.3 条目内容写作规范

| 要点 | 说明 |
|------|------|
| 简洁 | 单条 50-300 字，重点突出 |
| 结构化 | 可使用 Markdown 列表，方便 AI 解析 |
| 客观 | 描述事实而非评价，给出具体数据 |
| 独立 | 每条应自包含，不能依赖其他条目上下文 |
| 一致 | 不同条目中对同一事物的描述要保持一致 |

### 7.4 世界书结构规划

推荐按以下结构组织条目（以 30-40 条为例）：

| 模块 | 条目数 | 内容 |
|------|--------|------|
| ① 元数据与全局变量 | 1-2 条 | constant=true，始终注入的核心元数据 |
| ② 世界观与背景 | 3-5 条 | 世界基调、核心冲突、宇宙观 |
| ③ 地理区域 | 5-8 条 | 主要地点及其特征 |
| ④ 势力组织 | 4-6 条 | 主要势力、组织架构 |
| ⑤ 核心规则 | 5-8 条 | 等级体系、战斗规则、经济规则 |
| ⑥ 特殊系统 | 3-5 条 | 魔法/灵能/科技等子系统 |
| ⑦ 历史与传说 | 2-4 条 | 重要历史事件、神话传说 |
| ⑧ 生态与怪物 | 3-5 条 | 常见怪物、危险生物 |

### 7.5 定价参考

| 类型 | 条目数 | 推荐价格 | 说明 |
|------|--------|---------|------|
| 迷你设定 | 5-10 条 | 免费或 30 SEED | 特定场景的补充设定 |
| 标准世界书 | 15-30 条 | 60~120 SEED | 完整规则引擎，主流 |
| 大型设定集 | 30-50 条 | 120~200 SEED | 深度世界观，适合连载 |
| 旗舰级 | 50+ 条 | 200~500 SEED | 完整世界，超高复用性 |

## 八、最佳实践

### 8.1 从零开始创建世界书的步骤

1. **确定核心设定** — 写出 1-2 条元数据条目（constant=true），定义世界的基本规则
2. **规划条目目录** — 按模块列出需要编写的条目清单
3. **逐条编写** — 从最重要的规则条目开始，逐步扩展到细节
4. **关键词审查** — 每条写完后立即检查关键词是否自然、是否与其他条目重叠
5. **关联人物卡** — 通过资产链接关联相关的通用 NPC
6. **创建测试副本** — 使用本世界书创建一个测试副本，验证 AI GM 是否能正确引用
7. **迭代优化** — 根据测试中 AI GM 的表现，调整关键词和优先级

### 8.2 从 SillyTavern 导入

系统兼容 SillyTavern V2 的世界书格式：

```
POST /api/rpg/bridge
{
  "direction": "import",
  "type": "lorebook",
  "data": { ... ST V2 格式的世界书 ... }
}
```

导入时系统会自动处理格式转换。

### 8.3 常见问题

**Q: AI GM 不引用世界书内容怎么办？**
A: 检查关键词是否拼写正确，是否与玩家实际使用的词汇匹配。尝试增加 priority 值，或将核心条目设为 constant=true。

**Q: 条目太多导致 Token 超限怎么办？**
A: 减少 constant 条目数量（建议 ≤3 条）。降低低优先级条目的 priority 值。拆分大型世界书为多个小型世界书。

**Q: 导入的 MP/ST 世界书关键词混乱怎么办？**
A: 导入的世界书经常携带 Markdown 格式符号进入 keys 字段，需要手动清理。建议逐条检查并重写关键词。
