## 一、背景与愿景

### 1.1 为什么是现在？

FireSeed 平台已经完成了从"AI 小说工具"到"AI 创作社区"的跃迁：

- 拥有成熟的 DeepSeek AI 集成、实时流式对话、小说生成管线
- 建立了 SEED 代币经济系统和技能市场，形成了创作者生态
- Chat 社区已具备实时多人聊天基础
- 任务市场、众筹系统验证了供需匹配能力

与此同时，AI 角色扮演（AI RP）市场正在爆发式增长——AI Dungeon 月活超千万，SillyTavern GitHub 星标超 8 万，中文 TRPG 社区规模扩大超过 300%。**但市场存在一个巨大的空白：没有一款既兼容 SillyTavern 生态、又提供 Web 原生体验、还自带经济系统的 AI 跑团平台。**

### 1.2 核心洞察：三层差异化

```
+------------------------------------------------------------------+
|  Layer 3: 经济层                                                  |
|  SEED 代币 + 角色卡交易 + 模组众筹 + 创作者分成                    |
+------------------------------------------------------------------+
|  Layer 2: 生态桥                                                  |
|  SillyTavern V2 角色卡 ↔ 世界书 ↔ 聊天记录双向兼容                |
+------------------------------------------------------------------+
|  Layer 1: 体验层                                                  |
|  Web 原生 AI 跑团（AI GM + 骰子 + 地图 + 实时多人）               |
+------------------------------------------------------------------+
```

**为什么这是"天才方案"？**

1. **不替换，只桥接**：SillyTavern 用户是我们的种子用户，他们可以无缝导入角色卡继续游戏
2. **Web 优先，本地可选**：无需安装即可开团，Power User 可接入自建 SillyTavern 获取高级功能
3. **经济闭环**：每次掷骰、每段剧情、每个角色卡交易都流转 SEED 代币
4. **存量转化**：FireSeed 已有的 15 万+用户、AI 小说创作者天然是跑团玩家

## 四、功能详细设计

### 4.1 核心子系统：AI Game Master 引擎 (P0)

**功能描述**：AI GM 是跑团平台的大脑，负责推动剧情、裁决行动、扮演 NPC、维持规则一致性。

**用户故事**：作为玩家，我希望 AI GM 能理解我的行动意图、根据规则判定结果、推动剧情发展，以便获得沉浸式跑团体验。

**架构设计**：

```
玩家输入 ──→ 上下文构建器 ──→ LLM 调用 ──→ 结果解析器 ──→ 前端输出
                ↑                 ↑               ↓
            ┌───┴───┐       ┌─────┴─────┐   ┌────┴────┐
            │ 角色卡 │       │ 规则注入   │   │ 骰子结果 │
            │ 世界书 │       │ 剧情记忆   │   │ 状态更新 │
            │ 剧情记忆 │      │ 系统提示   │   │ 经验结算 │
            └───────┘       └───────────┘   └─────────┘
```

**业务规则**：

1. **上下文构建规则**：每次请求按以下优先级组装 Prompt：(a) 系统角色定义 → (b) 当前场景描述 → (c) 角色卡核心设定 → (d) 世界书相关条目 → (e) 剧情记忆摘要 → (f) 最近 N 条消息 → (g) 玩家输入
2. **规则注入规则**：根据当前跑团系统（DnD 5e / CoC 7th / 自定义），自动注入对应的规则摘要到 System Prompt
3. **骰子裁决规则**：当 AI GM 认为需要掷骰时，以 `[[D20+5]]` 格式标记，引擎自动解析并执行掷骰，将结果注入回 LLM 输出
4. **记忆压缩规则**：当上下文超过 8K tokens 时，自动对早期剧情进行摘要压缩，保留关键事件、NPC、决策点
5. **一致性校验规则**：每次 GM 输出后，检查是否与角色状态、剧情逻辑、已有设定冲突（规则引擎层校验）

**交互流程**：

1. 用户进入异时空房间，AI GM 自动生成开场描述
2. 用户输入行动（如"我拔出剑，对门卫使用威吓"）
3. 系统构建上下文 → 调用 LLM（DeepSeek） → AI GM 返回叙事+判定
4. 如需掷骰，AI GM 输出含 `[[D20+3]]` 标记 → 引擎执行掷骰 → 结果注入 → 继续生成
5. 关键决策点自动存档，作为后续剧情分支依据
6. 回合结束时自动更新角色状态（HP、道具、经验值）

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| LLM 超时 (＞15s) | 使用缓存的上一次 GM 输出模板，返回占位叙事 | "故事正在编织中… 请稍候" |
| LLM 返回违规内容 | 内容过滤器拦截，重新请求（降低温度 0.1） | "GM 思考了一下…" |
| 规则冲突 | 规则引擎优先，覆盖 LLM 输出 | 自动修正并在 GM 消息尾部标注 |
| 连续 3 次同质化输出 | 注入随机性增强 Prompt，提高 temperature | 自动触发剧情转折标记 |

**预设系统（Rule Templates）**：

| 预设 | 规则集 | 适用场景 |
|------|-------|---------|
| 龙与地下城 5e | AC/HP/属性/技能/法术位/经验值 | 奇幻冒险 |
| 克苏鲁的呼唤 7th | SAN/HP/技能检定/幸运/理智 | 恐怖调查 |
| 暗影狂奔 | 属性/技能/法术/黑客/装备 | 科幻赛博 |
| 自定义 | 用户完全自定义规则 | 任意场景 |
| 自由叙事 | 无规则约束，纯 AI 驱动 | 轻量角色扮演 |

### 4.2 核心子系统：掷骰引擎 (P0)

**功能描述**：支持标准 TRPG 骰子语法，可配置、可扩展、可审计。

**用户故事**：作为玩家，我希望能直观地掷出各种骰子并看到详细结果，以便在跑团中进行技能检定和伤害判定。

**支持的骰子语法**：

| 语法 | 含义 | 示例 |
|------|------|------|
| `D20` | 20 面骰 | `D20` → 15 |
| `2D6` | 2 个 6 面骰之和 | `2D6` → 9 (4+5) |
| `D20+5` | D20 + 加值 | `D20+5` → 18 (13+5) |
| `3D8+2` | 3D8 + 加值 | `3D8+2` → 17 (6+4+5+2) |
| `D20>15` | D20 判定（≥15 为成功） | → 成功(18) / 失败(7) |
| `D100` | 百分骰 | `D100` → 73 |
| `3D6K1` | 3D6 取最高 1 个 | `3D6K1` → 5 (2,3,5) |
| `4D6D1` | 4D6 去掉最低 1 个 | `4D6D1` → 12 (3+4+5, 去掉2) |

**业务规则**：

1. 所有掷骰结果记录到数据库，支持回放和审计
2. GM 模式的骰子对所有人可见；秘密骰子只对 GM 可见
3. 支持命运点/优势/劣势等 TRPG 通用机制
4. 骰子结果可触发 LLM 叙事分支（大成功/大失败特殊响应）

### 4.3 核心子系统：角色工坊 (P0)

**功能描述**：可视化角色创建与管理，兼容 SillyTavern V2 角色卡规范。

**用户故事**：作为玩家，我希望通过表单或导入方式创建角色，并能在 web 上随时查看和编辑角色信息，以便在不同的异时空中使用。

**角色卡数据结构（SillyTavern V2 兼容）**：

```typescript
interface CharacterCard {
  // SillyTavern V2 规范字段
  spec: 'chara_card_v2';
  spec_version: '2.0';
  data: {
    name: string;
    description: string;        // 角色外貌/性格简述
    personality: string;        // 性格特征
    scenario: string;           // 初始场景
    first_mes: string;          // 初始对话
    mes_example: string;        // 对话示例（少样本学习）
    system_prompt: string;      // 系统提示词
    post_history_instructions: string; // 历史后处理指令
    tags: string[];
    creator: string;
    character_version: string;
    // TRPG 扩展字段
    trpg: {
      system: string;           // DnD5e / CoC7th / 自定义
      level?: number;
      attributes: Record<string, number>;  // 属性（力量/敏捷/体质...）
      skills: Record<string, number>;      // 技能（潜行/说服/调查...）
      hp: { current: number; max: number };
      mp?: { current: number; max: number };
      san?: { current: number; max: number };  // 理智值 (CoC)
      equipment: string[];
      spells: string[];
      backstory: string;
      inventory: InventoryItem[];
    };
    character_book?: CharacterBook;  // 内嵌世界书
  };
}
```

**角色卡交互流程**：

1. 用户从「角色工坊」入口进入
2. 三种创建方式：从空白创建 / 从模板创建 / 从 PNG 导入（SillyTavern 格式）
3. 可视化编辑器：左侧为预览面板（实时显示角色卡渲染效果），右侧为编辑面板（分 tab：基础信息 → TRPG 属性 → 背景故事 → 对话示例 → 世界书）
4. TRPG 属性页支持规则预设（DnD 自动计算 AC/先攻，CoC 自动计算 HP/幸运）
5. 完成编辑后，角色卡可保存为平台格式或导出为 SillyTavern 兼容 PNG

**导入/导出**：

| 格式 | 导入 | 导出 | 说明 |
|------|------|------|------|
| SillyTavern V2 PNG | ✓ | ✓ | 全兼容，含头像+JSON |
| SillyTavern V2 JSON | ✓ | ✓ | 纯 JSON 格式 |
| 雾隐酒馆格式 | ✓ | ✓ | 平台扩展格式（含 TRPG 属性） |
| 独立头像 PNG | ✓ | - | 仅提取头像 |
| DnD Beyond 格式 | △ | ✓ | 部分字段映射 |

### 4.4 核心子系统：异时空/模组管理 (P1)

**功能描述**：多用户参与的跑团异时空管理，支持实时多人、异步回合、GM 协作。

**用户故事**：作为玩家，我希望创建或加入跑团异时空，与朋友在同一世界中互动，以便获得多人跑团体验。

**异时空模式**：

| 模式 | 参与者 | AI GM | 交互方式 | 适用场景 |
|------|-------|-------|---------|---------|
| **单人冒险** | 1 人 | AI GM | 实时叙事 | 新手入门、空闲时间 |
| **多人合作** | 2-6 人 | AI GM | 实时 / 异步 | 朋友联机跑团 |
| **人类 GM 模式** | 1 GM + N 玩家 | 辅助 | 实时 | 传统 TRPG 数字化 |
| **混合模式** | 1 人+AI NPC | AI GM | 实时 | 半单人带 AI 同伴 |

**异时空生命周期**：

```
创建异时空 → 设置模组/世界观 → 邀请玩家 → 导入角色卡
    ↓
角色确认 → AI GM 开场 → 正篇开始
    ↓
┌─────────────────────────────┐
│ 回合循环: 描述 → 行动 → 判定 → 反馈  │
└─────────────────────────────┘
    ↓
存档/暂停 → 继续 → ... → 异时空完结 → 战报生成
```

**实时多人架构**：

```
User A (Web) ──┐
User B (Web) ──┼── SSE / WebSocket ──→ AI GM Engine ──→ DeepSeek
User C (Web) ──┘                              │
                                         ┌────┴────┐
                                         │ 状态同步器 │
                                         │ (SQLite)  │
                                         └─────────┘
```

### 4.5 核心子系统：世界书编辑器 (P1)

**功能描述**：可视化编辑 SillyTavern 兼容的 Lorebook（世界书/知识书），管理世界观设定。

**用户故事**：作为创作者，我希望创建结构化的世界观知识库，在跑团中按需自动注入给 AI GM，以保持世界设定的一致性。

**世界书条目结构**：

```typescript
interface LorebookEntry {
  id: string;
  keys: string[];           // 触发关键词
  content: string;          // 条目内容
  enabled: boolean;
  selective: boolean;       // 是否选择性注入
  priority: number;         // 优先级 (0-100)
  secondary_keys?: string[]; // 辅助触发词
  constant?: boolean;       // 是否始终注入
  position?: string;        // 注入位置 (before/after)
}
```

**世界书层级**：

```
Level 0: 全局设定（始终注入）
  ├── 世界名称、核心冲突、通用规则
Level 1: 区域设定（关键词触发）
  ├── 城市描述、重要 NPC、地区规则
Level 2: 剧情设定（动态注入）
  ├── 当前任务、活跃 NPC、事件状态
Level 3: 角色私密设定（仅本人可见）
  └── 角色的秘密目标、隐藏身份
```

### 4.6 生态桥：SillyTavern 兼容层 (P1)

**功能描述**：双向打通 SillyTavern 生态，让用户自由迁移角色、世界和聊天记录。

**双向兼容矩阵**：

```
                    SillyTavern ←→ 雾隐酒馆
                    ─────────────────────
角色卡 (.png)          ✓ 导入/导出 ✓
角色卡 (.json)         ✓ 导入/导出 ✓
世界书 (.json)         ✓ 导入/导出 ✓
聊天记录 (.jsonl)      ✓ 导入 ✓
预设配置 (.json)       → 单方向导入
扩展/插件              △ 通过 API 桥接
```

**SillyTavern API 代理模式**（高级功能）：

```
用户 SillyTavern → 配置 API 端点 → fireseed.online/api/st-proxy
                                          │
                                    ┌─────┴─────┐
                                    │ 代理认证层   │
                                    │ SEED 代币消耗│
                                    │ 请求过滤器   │
                                    └───────────┘
                                          │
                                    雾隐酒馆 AI GM 引擎
                                          │
                                    DeepSeek / Claude
```

高级用户可将自己的 SillyTavern 实例连接到 FireSeed 的 AI GM 引擎，在本地 UI 中获得 FireSeed 的 AI GM 能力。每次 API 调用消耗 SEED 代币。

### 4.7 经济系统：SEED 代币循环 (P1)

**经济飞轮**：

```
                     ┌─────────────────────┐
                     │ 创作者发布角色卡/模组  │
                     └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │  用户购买 (SEED 支付) │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │  创作者获得分成 (70%)  │
                    │  平台抽取 (20%)       │
                    │  推荐人奖励 (10%)     │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │  SEED 消耗场景        │
                    │  AI GM 调用          │
                    │  高级骰子特效         │
                    │  角色卡高级编辑       │
                    │  模组众筹             │
                    └──────────┬──────────┘

                    ┌──────────▼──────────┐
                    │  回购/销毁机制        │
                    │  燃烧部分 SEED       │
                    └─────────────────────┘
```

**定价模型**：

|------|-----------|------|

| 角色卡创建 | 免费 | 基础功能免费 |
| 角色卡高级编辑（AI 辅助） | 10 SEED | AI 润色角色设定 |
| 世界书创建 | 免费 | 基础功能免费 |
| 世界书 AI 扩展 | 5 SEED/次 | AI 自动生成设定条目 |

## 七、关键设计决策

### 7.1 为什么选择 DeepSeek 作为主力 AI GM？

- **已集成**：FireSeed 已有 DeepSeek API 集成，零额外成本
- **推理能力强**：DeepSeek-R1 系列在逻辑一致性和长文本理解上表现优秀
- **成本优势**：相比 Claude/GPT，DeepSeek API 价格低 80-90%
- **可选后备**：支持多模型路由，高复杂度场景可切换到 Claude

### 7.2 SSE 而非 WebSocket？

- SSE（Server-Sent Events）与 Next.js 14 App Router 天然兼容
- 跑团场景主要是服务器→客户端的单向叙事流
- 玩家输入是 REST 请求，AI GM 输出是 SSE 流
- 减少连接管理和基础设施复杂度

### 7.3 角色卡存储在 SQLite 而非文件系统？

- 与现有 FireSeed 架构一致（SQLite 已用于所有业务数据）
- 便于搜索、排序、权限管理
- JSON 字段存储角色卡完整数据，无需 Schema 变更
- 导出时再组装为 PNG/JSON 格式

### 7.4 小说→模组转换器的设计思路

FireSeed 已有大量 AI 生成的小说，这些小说天然适合转化为跑团模组：

```
小说章节 ──→ AI 分析 ──→ 提取角色、场景、事件
                    ↓
              生成模组结构：
              ├── 世界观设定书
              ├── NPC 角色卡列表
              ├── 剧情分支树
              └── 遭遇战/谜题设计
```
