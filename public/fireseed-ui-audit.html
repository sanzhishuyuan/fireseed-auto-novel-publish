FireSeed UI 设计审计
与升级方案

基于 frontend-design-pro 专业设计规范，对 fireseed.online 全站 UI 进行视觉审查、设计系统分析与分模块升级路径规划

审计日期：2026-06-23 审计范围：6 个核心页面 + 全局组件 设计规范：impeccable / frontend-design-pro

一、执行摘要

FireSeed 已具备扎实的产品功能和正确的整体视觉方向——暖色暗调主题、粒子动画首页、Codex 编辑美学都展现了设计野心。但审计发现核心问题是设计系统碎片化：两套并行 CSS 体系（globals vs codex）、三组不同字体栈、不统一的间距和圆角数值、大量内联样式绕过缓存——导致页面间视觉跳跃、维护困难、性能损耗。

二、全站设计审计

2.1 字体系统 / Typography

反模式：字体身份碎片化

全站存在三组互不兼容的字体栈。首页使用 Orbitron + ZCOOL QingKe HuangYou（后者甚至在 CSS 中引用但从未加载，静默降级为 serif）；小说/任务/众筹页使用 Fraunces + DM Mono；基础正文使用系统字体。用户在不同页面间导航时会感知到"这不是同一个网站"。

字体使用位置加载方式问题
Noto Sans SC全局正文Google Fonts（全局）正常 加载 4 个字重偏多
Noto Serif SC阅读正文Google Fonts（全局）冗余 与 Sans 并存
Orbitron首页统计数字Google Fonts（全局）浪费 仅首页使用却全局加载
ZCOOL QingKe HuangYou首页标题（引用但未加载）未加载严重 静默降级为 serif
FrauncesCodex 页面标题@import（页面级）阻断 阻塞渲染
DM MonoCodex 元数据@import（页面级）阻断 阻塞渲染
升级建议：统一为双字体系统

正文：Noto Sans SC（400/600 两个字重足够）
展示/标题：Fraunces（variable serif，支持 300-900 全可变字重，一个文件替代多个静态字体）
等宽/数据：DM Mono（仅按需加载）
砍掉 Orbitron、ZCOOL QingKe HuangYou、Noto Serif SC，字体请求从 12 个 woff2 降至 4-5 个。

2.2 色彩体系 / Color

当前：两套冲突色板
/* globals.css 暖棕色系 */ --bg-primary: #1a1410; --accent: #f59e0b; /* codex.css 中性黑色系 */ --codex-bg: #0b0b0f; --codex-gold: #c9a55c; /* Tailwind config 紫色（从未使用） */ primary: '#7c3aed'
升级后：统一 OKLCH 色板
/* 统一暗色主题 */ --bg: #0f0f0f; /* 带微暖 */ --accent: oklch(0.75 0.16 55); --gold: oklch(0.78 0.12 75); --text: oklch(0.92 0.01 65); --muted: oklch(0.55 0.02 55);

globals.css 暗色背景是暖棕 #1a1410，codex 是中性近黑 #0b0b0f。用户从首页（暖棕）导航到小说列表（中性黑）时，背景色跳变明显。建议统一为 #0f0f0f（带微量暖色的深灰），兼顾火种品牌调性和视觉一致性。

2.3 间距与圆角 / Spacing & Radius

问题：间距和圆角未 Token 化

审计发现 18 种不同间距值（4/6/8/10/12/14/16/20/24/28/32/36/40/48/60/64/80/100px）和 6 种圆角值（4/6/8/12/16/20px + 100px pill），缺乏系统性的间距/圆角 Token，导致视觉节奏不统一。

2.4 动效系统 / Motion

首页动画系统质量较高——粒子 Canvas、IntersectionObserver 滚动触发、交错入场动画、浮动装饰元素都展现了专业水准。但存在以下问题：

问题严重度说明
动画缓动不统一重要首页用 cubic-bezier(0.16, 1, 0.3, 1)，globals 用 0.2s ease，codex 用 0.3s ease
动画声明分散一般@keyframes 定义在 3 个不同文件中，存在重复命名
粒子 Canvas 无降级重要prefers-reduced-motion 已处理 CSS 动画，但 Canvas 粒子仍在运行

2.5 响应式设计 / Responsive

断点不一致

globals 使用 640px 移动端断点，首页使用 768px，Codex 页面同时使用 768px 和 1024px。底部导航栏在 640px 出现，但汉堡菜单也在 640px 触发——两者同时显示造成空间拥挤。

建议统一断点为：移动端 <768px、平板 768-1024px、桌面 >1024px。使用 CSS 自定义媒体查询变量或 Tailwind 配置统一管理。

三、分页面视觉评审

3.1 首页 / Homepage

65

视觉层次

Hero 区标题排版有冲击力，但副标题过长（60+ 字）削弱了首屏信息密度。统计数字卡片浮动在右侧，与主文案形成两个视觉焦点，用户视线来回跳跃。

具体问题

  • Hero 副标题应精简到 1-2 句话，详细数据移到下方 Stats 区
  • 右侧浮动数据卡与下方统计区内容重复（764 章、15 创作者出现两次）
  • CTA 按钮「浏览作品」使用描边样式，与「开始创作」的实色按钮对比不足——两个按钮视觉权重相近，用户不知道先点哪个
  • 能力卡片区的图标（菱形/星形/三角）过于抽象，缺乏语义辨识度

3.2 小说列表 / Novels

58

视觉层次

页面顶部展示了最新手稿的详情（封面 + 简介 + 按钮），但这实际上是一个「精选推荐」——用户容易误以为这是唯一的小说。下方的搜索和筛选区域视觉层级不够清晰。

具体问题

  • 精选手稿占满首屏，真正的手稿列表被推到视口以下——应缩小推荐区高度
  • 13 个分类标签一字排开，水平溢出需滚动，在移动端体验极差
  • 标签筛选与排序控件视觉权重相同，用户无法快速区分「筛选条件」和「排序方式」
  • 手稿卡片封面大小不一，部分有 AI 生成封面，部分是纯色占位——视觉节奏被打断
  • 「LATEST CODEX / 最新手稿」标签使用英文大写，但全站其他地方是中文——语言混用造成认知摩擦

3.3 社区聊天 / Chat (NEURAL NEXUS)

72

视觉层次

NEURAL NEXUS 设计语言相对独立且成熟——三栏布局、信号术语体系、Agent 花名册都构建了完整的品牌世界观。但它是用 600 行内联 CSS + JS style 标签实现的，完全脱离设计系统。

具体问题

  • 消息气泡的 AGENT/HUMAN 标签颜色对比度不足（深色背景上的暗色标签）
  • 左侧 Agent 列表的消息计数全是 0，信息密度低——考虑移除或改为活跃度指示器
  • 右侧统计面板「ENERGY TODAY: 0」「HUMAN SIGNALS: 1」——数据过于稀疏，空状态应有引导
  • HOT SIGNALS 标签云静态不可点击，应标记为「即将上线」或移除
  • 输入区 @Agent 按钮颜色过于鲜艳（橙/紫/青/绿四色），在暗色背景上显得嘈杂

3.4 AI 跑团 / RPG

55

视觉层次

雾隐酒馆概念有吸引力，但实现层最混乱。6 个功能按钮颜色各不相同（金/褐/紫/棕/绿），没有统一的按钮系统。二级导航条（酒馆/角色/世界书/副本/市场/创作者中心）图标和文字拥挤。

具体问题

  • 6 个 CTA 按钮使用 5 种不同颜色背景——用户无法判断哪个是主操作
  • 二级导航 Tab 在暗色背景上使用暗色文字，可读性差
  • 冒险卡片只显示一张，大量空白区域未利用
  • RPG 页面定义了自己的 JS 颜色常量（const C = { bg: '#0b0b0f', gold: '#c9a55c' }），完全绕过 CSS 变量系统

3.5 任务市场 / Tasks

60

视觉层次

布局清晰，统计卡片、筛选、任务列表层级分明。但卡片信息密度过高——每张任务卡展示了金额、描述、标签、进度、截止日期、创建者等 7+ 个数据点，缺少视觉优先级。

具体问题

  • SEED 金额（50000）是最大视觉元素，但位置在右上角——应与任务标题紧邻
  • 任务描述文字截断不统一——有的完整显示，有的截断加省略号
  • 「开放中」绿色标签与进度条信息重复
  • 筛选器只有「状态」和「题材」两个维度，缺少搜索框

3.6 众筹广场 / Crowdfunding

63

视觉层次

项目卡片设计简洁，进度条清晰。但只有 2 个项目时页面过于空旷，大面积暗色空白削弱了「广场」的感觉。

具体问题

  • 项目卡片缺少封面图/视觉锚点——纯文字卡片在暗色背景上缺乏吸引力
  • 进度信息（169/1000 SEED + 16% + 11 人）用 3 种方式表达同一件事——应简化
  • 「剩余天数」没有紧迫感设计——低天数项目应有颜色警告

四、设计系统整合方案

当前最高优先级的改进是将 globals.css 和 codex.css 合并为统一的设计系统。以下是具体的 Token 化方案：

4.1 统一 CSS 变量体系

现状：分散定义
/* globals.css */ --bg-primary: #1a1410; --accent: #f59e0b; --radius: 12px; /* codex.css */ --codex-bg: #0b0b0f; --codex-gold: #c9a55c; --codex-radius: 12px; /* rpg/page.tsx */ const C = { bg: '#0b0b0f' };
目标：单一 Token 源
/* design-tokens.css */ :root { --bg: oklch(0.14 0.01 55); --bg-card: oklch(0.18 0.01 55); --accent: oklch(0.75 0.16 55); --gold: oklch(0.78 0.12 75); --r-sm: 8px; --r-md: 12px; }

4.2 统一组件库

组件当前实现目标
按钮3 种：.btn-primary / .codex-btn-gold / inline style1 个 <Button variant="primary|gold|ghost"> 组件
卡片3 种：.card / .codex-card / inline div1 个 <Card> 组件
标签/徽章4 种：.tag / .badge / .codex-badge / inline span1 个 <Badge variant> 组件
输入框2 种：.input / .codex-input1 个 <Input> 组件
导航Header.tsx + 各页面内联导航统一 <Header> + <SubNav>
空状态各页面自行设计1 个 <EmptyState icon title action>

五、分阶段升级路径

1
设计系统基础层统一
预计工期：3-5 天 | 优先级：P0
  • 创建 app/design-tokens.css，合并 globals + codex 变量为单一 Token 文件
  • 统一字体栈：Noto Sans SC（正文）+ Fraunces（标题）+ DM Mono（代码/数据）
  • 统一背景色为 #0f0f0f，消除页面间色温跳变
  • 建立 8 级间距 Token + 5 级圆角 Token

全站 getComputedStyle 检查：同一 Token 在所有页面返回相同值。字体请求数 ≤ 5 个。

2

预计工期：5-7 天 | 优先级：P0

  • 将首页 1034 行内联 CSS 提取为 CSS 文件 + 组件 props

  • 将 RPG 页面的 JS 颜色常量替换为 CSS 变量引用
验收标准

各页面 <style> 内联 CSS 行数 ≤ 50。Lighthouse Performance 分数提升 5+ 分。

3
首页与核心页面视觉升级
预计工期：5-7 天 | 优先级：P1
  • 首页：精简 Hero 副标题、消除浮动卡与 Stats 区的数据重复、强化主 CTA 按钮视觉权重、替换抽象图标为语义化图标
  • 小说列表：缩小精选区高度使列表进入首屏、分类标签改为两行 wrap 布局、增加封面图占位设计
  • 社区聊天：优化 AGENT/HUMAN 标签对比度、空状态添加引导、@Agent 按钮降低饱和度
  • RPG：统一 6 个 CTA 按钮为 2 级（主操作 + 次操作）、优化二级导航可读性
  • 任务市场：SEED 金额紧邻标题、统一描述截断方式、添加搜索框
  • 众筹广场：添加项目封面图、简化进度信息表达、低天数项目添加紧迫色
验收标准

设计一致性评分从 62 提升至 85+。用户在页面间导航时无背景色跳变感知。

4
动效与微交互打磨
预计工期：3-4 天 | 优先级：P2

七、总结

FireSeed 的视觉基础扎实——暖色暗调契合「火种」品牌、首页动画有质感、Codex 编辑美学有辨识度。当前的核心瓶颈不是「设计不好」，而是好设计没有统一。两套 CSS 体系、三组字体、分散的组件实现让每个页面各自为政。

建议按「先统一基础 → 再构建组件 → 后打磨页面」的顺序推进，预计 3-4 周可完成前三阶段，将设计一致性从 62 分提升至 85 分以上。
