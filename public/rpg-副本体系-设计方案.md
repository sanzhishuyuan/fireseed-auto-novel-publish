# 「副本」体系 × 资产跨引用 — 设计方案

> 版本：v1.0 | 2026-06-12
> 涉及：术语统一、数据模型、API、前端、经济激励


## 一、术语统一

### 1.1 名词对照表

| 中文（旧） | 中文（新） | 系统标识 | 含义 |
|------------|------------|----------|------|
| 战役 | **异时空** | `campaign` | 玩家正在进行的游戏会话（推荐用异时空） |
| 战役模组 | **副本** | `module` (asset_type) | 预制的可售卖冒险包 |
| 人物卡 | 人物卡（通用/专用） | `character` | 角色卡，分「通用」和「专用」两种 |
| 世界书 | 世界书 | `lorebook` | 世界观设定集 |

> **选「异时空」而非「浮世绘」**：浮世绘虽有诗意，但作为日本江户时代版画的专有名词，易造成认知偏差。异时空（different dimension/timeline）在中国网文和游戏中高频出现，用户一看就懂——每次冒险都是进入一个不同的时空。未来可作为产品线品牌名（如「雾隐酒馆·异时空系列」）。

### 1.2 改动范围

| 位置 | 当前 | 改为 |
|------|------|------|
| 类型字面量 `asset_type` | `'module'` | 保留不变（代码层） |
| TYPE_LABEL 前端显示 | `'战役模组'` | `'副本'` |
| TYPE_ICON | `⚔️` | `🏛️` |
| 权限名 `sell_module` | `sell_module` | 保留（代码层） |
| 权限标签 | `'上架战役模组'` | `'上架副本'` |
| 市场描述文案 | `'战役模组'` | `'副本'` |
| API 返回字段 | `module` | 前端映射显示 |
| `campaign` 前端文案 | `'战役'` | `'异时空'` |

**原则**：数据库字段、TypeScript 类型、API 参数等代码层不动，仅前端文案和用户可见提示更新。改动最小，不影响数据。

### 1.3 人物卡：专用 vs 通用

由创作者创作时决定：

| 类型 | 含义 | 使用方式 | 市场行为 |
|------|------|----------|----------|
| **通用卡** | 独立角色，不绑定任何副本 | 可在任意异时空使用，可被副本引用为 NPC | 单独上架销售 |
| **专用卡** | 绑定某个副本的专属角色 | 作为该副本的预设 NPC 出现，自带剧情关联 | 随副本捆绑销售，也可单独出售 |

**专用卡的双重身份**：
- 买到对应副本时，专用卡自动可用
- 创作者可选择是否允许单独售卖
- 市场上显示「本卡为 xxx 副本专用 NPC」标签


## 二、资产跨引用系统

### 2.1 核心概念

三类资产（人物卡、世界书、副本）之间建立可关联、可引用、可组合的关系网络：

```
人物卡 ←──────────────→ 副本
  │                        │
  │ (所属世界/阵营)         │ (关联世界观)
  ↓                        ↓
世界书 ←──────────────→ 副本
```

### 2.2 使用场景

**场景 A：GM 设计副本**
1. GM 创建一个副本「古神遗迹之谜」
2. 从市场挑选 3 张人物卡作为 NPC（Boss、向导、叛徒）
3. 关联 1 部世界书「雾都纪元·诡秘克苏鲁」作为世界观基底
4. 上架市场，购买者可获得：副本 + 可选 NPC 人物卡捆绑包

**场景 B：创作者设计人物卡**
1. 创作者画了一张「暗夜精灵刺客」人物卡
2. 标注适配副本：「古神遗迹之谜」
3. 买家购买人物卡时，能看到它可用于哪些副本

**场景 C：买家选购**
1. 看到副本「古神遗迹之谜」→ 已关联 3 个 NPC 和 1 部世界书
2. 可单独买副本（自备角色），也可买「完全体捆绑包」(副本 + NPC包 + 世界书折扣)
3. 购买的 NPC 自动成为异时空中的预设角色

### 2.3 数据模型

#### 新表：`rpg_asset_links`

```sql
CREATE TABLE IF NOT EXISTS rpg_asset_links (
  id TEXT PRIMARY KEY,
  source_type TEXT NOT NULL,    -- 'module' | 'character' | 'lorebook'
  source_id TEXT NOT NULL,
  target_type TEXT NOT NULL,    -- 'character' | 'lorebook' | 'module'
  target_id TEXT NOT NULL,
  role TEXT DEFAULT '',         -- 关联角色：boss/ally/merchant/quest_giver/setting
  sort_order INTEGER DEFAULT 0,
  is_required INTEGER DEFAULT 0,  -- 是否必需（购买副本时强制推荐）
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (source_id) REFERENCES …,
  FOREIGN KEY (target_id) REFERENCES …
);
```

#### `role` 可选值

| 值 | 含义 | 适用场景 |
|----|------|----------|
| `boss` | BOSS 级敌人 | 副本→人物卡 |
| `elite` | 精英怪物 | 副本→人物卡 |
| `ally` | 盟友/伙伴 | 副本→人物卡 |
| `merchant` | 商人 | 副本→人物卡 |
| `quest_giver` | 任务发布人 | 副本→人物卡 |
| `faction_leader` | 势力领袖 | 副本→人物卡 |
| `setting` | 世界观/场景 | 副本→世界书 |

#### 人物卡扩展字段

```sql
ALTER TABLE rpg_characters ADD COLUMN module_id TEXT DEFAULT NULL;  -- 所属副本
ALTER TABLE rpg_characters ADD COLUMN npc_role TEXT DEFAULT '';     -- NPC 角色
ALTER TABLE rpg_characters ADD COLUMN npc_level INTEGER DEFAULT 1;  -- NPC 等级/挑战等级
```

### 2.4 API 设计

| 端点 | 方法 | 功能 |

### 2.5 经济激励模型

这是系统能否持续运转的关键。设计原则：

1. **引用免费，捆绑分润**
   - 引用他人人物卡到副本是免费的（促进生态丰富度）
   - 当买家选择捆绑购买时，收入按比例分润

2. **捆绑包分润比例**

| 参与方 | 分润比例 | 说明 |
|--------|----------|------|
| 副本作者 | 60% | 策划、设计、编排的贡献 |
| NPC 人物卡作者 | 按张均分 25% | 每张 NPC 卡按售价比例分配 |
| 世界书作者 | 10% | 世界观授权 |
| 平台 | 5% | 交易手续费 |

3. **单人卡的分润公式**

```
单张 NPC 分润 = 捆绑包总价 × 25% × (该卡原价 ÷ 所有 NPC 原价总和)
```

4. **激励示例**

```
副本「古神遗迹之谜」售价 300 🌱
  捆绑包售价 450 🌱（含 3 张 NPC 卡）
  
  副本作者：450 × 60% = 270 🌱
  NPC 作者甲（原价100）：450 × 25% × (100/350) ≈ 32 🌱
  NPC 作者乙（原价150）：450 × 25% × (150/350) ≈ 48 🌱
  NPC 作者丙（原价100）：450 × 25% × (100/350) ≈ 32 🌱
  世界书作者：450 × 10% = 45 🌱
  平台：450 × 5% = 22 🌱
```

5. **双重购买保护**
   - 如果买家已拥有某张引用的人物卡，捆绑包自动减价（去掉该卡原价）
   - 分润时不再给已售卡片的作者重复分润

### 2.6 购买模式增强

当前 `buyAsset()` 只处理单资产购买。需扩展支持：

```typescript
interface BundlePurchase {
  mainListingId: string;           // 副本 listing ID
  includeLinkedChars: boolean;     // 是否购买关联 NPC
  includeLinkedLorebooks: boolean; // 是否购买关联世界书
  excludeOwned: string[];          // 已拥有的资产 ID 列表
}
```

购买流程：
1. 买家点击「购买副本」或「购买完全体捆绑包」
2. 系统检查买家已拥有哪些关联资产
3. 计算最终捆绑价（自动扣减已拥有部分）
4. 执行一笔总扣款，按分润比例分别计入各创作者账
5. 所有关联资产进入买家资产库

### 2.11 风险与注意事项

1. **循环引用**：A 副本引用 B 人物卡，B 人物卡标注所属 A 副本 → 数据上允许，前端需去重显示
2. **删除级联**：某资产下架或删除时，其引用关系应自动标记失效（soft delete）
3. **版本漂移**：人物卡更新后，副本中引用的版本可能是旧的 → 建议「引用时快照关键数据（名称、价格），详细数据实时查询」
4. **性能**：一个副本引用数十张 NPC 卡时，详情页加载需做 N+1 优化 → 用 JOIN 一次性查出所有关联数据


## 三、总结

| 维度 | 当前状态 | 目标状态 |
|------|----------|----------|
| 术语 | 战役模组 + 战役（TRPG 术语） | 副本 + 异时空（游戏通用术语） |
| 资产间关系 | 孤立的三个品类 | 可互相引用的网络 |
| 购买方式 | 单品购买 | 单品 / 捆绑包 / 完全体 |
| 创作者激励 | 仅单品销售收益 | 引用来带量 + 捆绑分润 |
| 内容复用 | 低（各自独立） | 高（排列组合出新副本） |
